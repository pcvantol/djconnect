## Transport and inventory

Use the existing authenticated paired Hybrid transport, same installation/operation epoch/UUIDv7 envelope and original PairedAuthority. Native ios/macos only. Add read operations `ask_dj/moments`, `ask_dj/moments/status`; action operations `ask_dj/moments/request`, `ask_dj/moments/cancel`. No route accepts caller Profile/account authority. Inventory is a pure loaded-state read, never a fetch/prewarm. Existing Help and reaction contracts are unchanged.

HTTP read adapter: `POST /api/djconnect/v1/transport/read` with `{contract_version:1,operation,payload,identity:{device_id,client_type}}`; same TLS ingress and paired authority. WebSocket uses existing `djconnect/read`. Global `/capabilities` and Hybrid/context advertise `ask_dj_moments`, with the exact read/action operation sets. No dependence on reaction observers or activated speech output.

All copy uses the original confirmed Session locale, returned as `language`. Menu labels and unavailable reason_labels are five-language maps for the client interface locale; story and pending/error copy stay in the confirmed original Session language. `pending_text` is a localized string on each inventory row and response, generated without a model from captured Persona/Mood. The request does not override Session language/settings.

Inventory payload: `{contract_version:1, session_id:<original>}`. Response:
`{success:true, contract_version:1, session_id, language, title:"Ask DJ: Moments", types:[{type_id, moment_type, order, label:{en,nl,de,fr,es}, available, reason:null|code, reason_text:null|localized_string, reason_labels:null|{en,nl,de,fr,es}, history_policy, subject:{subject_ref, kind, title, subtitle}, pending_text:localized_string}]}`.
`subject_ref` is an opaque bounded expiring server-owned capture bound to paired device, Profile, original Session/settings and exact original playback/fact identities. It is a locator, never an independent credential. No client-supplied title, fact, URL, history or identity may become evidence. Capacity/expiry is explicit; reopening cannot renew source facts.

Request payload: `{contract_version:1, session_id, type_id, subject_ref}` inside the existing operation envelope `{contract_version:1,operation_id:<UUIDv7>,operation_epoch,operation:"ask_dj/moments/request",payload}`. This is an explicit rich content request, not an Ask DJ text turn. No extra Send/chat turn. Pending copy is curated Core five-language Mood/Persona-aware text; no extra model call.

Status read payload: `{contract_version:1,session_id,operation_id:<original request>}`. Cancel action payload: `{contract_version:1,session_id,request_operation_id:<original request>}` (its own outer operationID identifies cancellation). Status/cancel require original paired ownership and never transfer requests to another Profile or device.

## Result and presentation

Domain response: `{success,contract_version:1,session_id,operation_id,type_id,language,state,pending_text,message,result,entry_id,moment_id,error}`. The ordinary HTTP action response adds the existing `operation_receipt` and `result_available` at this same root. WebSocket retains its existing result envelope. Unknown pre-admission failures use the existing `{success:false,error}` boundary; restart recovery/cancel-before-send may omit language/message/type and return `pending_text:null`. No decoder may require result-only fields on those responses. State is `pending|accepted|not_found|temporarily_unavailable|denied|cancelled|accepted_result_unavailable`. Error is a stable code ornull. Pending/error text is feedback, never a Moment/history body.

Accepted result: `{moment:<same canonical DJMoment serialization>,entry_id:<original retained entry ornull>,retention:"retained"|"not_retained",history_state:"content_retained"|"receipt_only"|"not_retained",presentation_admission:{contract_version:1,moment_id,owner_only:true,display_allowed,expires_at,requires_spotify_attribution,source_expires_at},session_media:[<existing scoped envelopes>],session_speech:{schema_version:1,moments:[<existing descriptor>]}}`. Each inventory `moment_type` is the Core renderer-family authority and must match the accepted original Moment type. Existing validated Moment actions are rendered normally and never executed merely by selection, status or rendering. No second rich type/content representation. Exact accepted MomentID is the dedup key. A source-valid explicit display admission works while paused or after track change, without weakening ordinary spontaneous current-Moment admission. Display lifecycle begins when actually visible on the initiating client, bounded by source/owner/media rights; recovery does not restart a presentation window or autoplay. Other clients may immediately read already accepted history. Requested Moments are excluded from ordinary spontaneous current-candidate selection; they remain in active Flow and history. Thus collapse, the local20-second budget or reconnect cannot reopen the same rich current card. `expires_at` is the fixed minimum of original operation/proof and actual source/research/Bulletin deadlines, serialized from the paired publication clock. It is never the local20-second budget. Original semantic `created_at` remains unchanged even when research delays publication.

Success uses existing Knowledge assembly, Moment creation/narration assessment, presentation composer, durable Session history and Flow/Broadcast. The initiating explicit owner must bypass only proactive cadence/playing/remaining-track-fit, without consuming/resetting proactive ledgers or allowing public/shared publication. Original source eligibility, cost, typed evidence, quality and privacy retention remain mandatory. Immediate `_async_persist_moment` semantic acceptance precedes publish/delivery; source metadata and operation provenance are retained with the original entry. A response lost after commit resolves the original Moment/history; no new model run. No-retention policy returns `not_retained`, never silently enables consent; restart may honestly report accepted_result_unavailable.

## Concurrency and fences

One bounded pending request per Profile/Session across devices. Duplicate operationIDs use the existing durable journal. Original identity is fixed before any await, including cancel-before-admission; cancellation synchronously fences pending work. The final authorizer runs inside the existing persistence transaction before commit. Once commit succeeds, cancel cannot claim undo/deletion. Session/Profile/account/settings/provider/privacy withdrawal invalidates pending generation; track change preserves frozen subject where original rights remain valid. Proactive/reaction events cannot replace the initiating pending/result card, but their genuine accepted history remains intact.

Speech uses the existing original-Moment Session speech owner and processor/source rights. Only the first accepted initiating response may expose the existing configured automatic policy; status, reconnect, generic Broadcast and other devices always have autoplay false. `automatic_start_expires_at` binds the actual publication clock plus the existing12-second start admission, never arrival or original seed creation time. Cancellation closes any not-yet-started automatic admission. Existing selected-speaker delivery is requester-bound and follows its original output/source grants; private Bulletin remains manual-only where its source contract requires that.

A source-admitted descriptor may carry `user_requested:true` and `moment_type`. Only this original committed proof, or its closed durable original-operation provenance after normal retained-entry/source/privacy admission, permits manual **local** replay at `text_only`. It never authorizes automatic or speaker output. History reads return a fresh existing `entry.session_speech` descriptor; prepare3 revalidates the exact original entry, text, settings revisions, owner and rights. A row type or client flag alone is no grant. Private Bulletin history is `receipt_only` with `retention:not_retained`; an entryID does not promise archival prose or historical speech. Ordinary retained families keep the exact original accepted content under their existing retention policy. No synthesis on menu/status/open, no new autoplay contract or duplicate narration. Live media reuses exact media3 grants/managed paths and immutable original photo references; transient bytes failure retains text, actual withdrawal fails closed.

## Producer reuse and failure semantics

Inventory and status call no source/model owner. Capture freezes already loaded facts and normalized catalogue identities and the actual earlier published recording/album contexts. Existing artist topic rotation includes live_performance, members, recording and background inside the selected artist/recording owner; selecting artist_story never silently publishes a Live-impressie. Selecting Live never substitutes artist prose. Source-approved typed narration acceptance is required for every rich producer; an ordinary fallback string is not success.

One bounded request context records only whether an existing public fetch/resolver/model transport reported a transient rate limit, server/network failure or timeout. It holds no authority or source text. This distinguishes temporarily_unavailable from honest no-find/quality rejection without adding retries or work on a read. Unselected families and the proactive path retain their existing budgets and guards.

Per-request narration and speaker closures reuse the original paired configuration without overwriting the spontaneous owner. Normal device-status cache updates do not revoke an original subject; actual profile/session, settings, credentials/scopes, source, content withdrawal and final transaction authorization still do. The durable journal confirms a genuine SQLite commit even when its later display admission is withdrawn. Cancellation after commit closes presentation, never erases or relabels acceptance.

Bulletin retains its existing immutable candidate-derived MomentID, required by the existing Bulletin acceptance proof. Music-family requested IDs are deterministically bound to the UUIDv7 operation before narration; this is not a universal Bulletin ID rule. Both families persist the original operation provenance and resolve the same actual MomentID/entryID on recovery. A Bulletin receipt is dj_publication metadata, never a retained dj_moment text/speech grant; the retained-provenance predicate deliberately rejects it. Current source-valid Bulletin manual use remains bound to its original private proof and existing processor rights.
