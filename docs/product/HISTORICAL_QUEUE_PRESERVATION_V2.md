# Historical playback: queue-preservation contract V2

The user requirement is an exact retained recording played while every other queued occurrence keeps its identity, multiplicity and relative order. Original A/B/A occurrences must remain distinguishable. Exact recording identity alone is insufficient. The existing Spotify ordinary-play operation cannot prove that invariant, and no qualified atomic provider operation is available.

The server therefore advertises `historical_exact_track_playback:false` with contract version `2`. Both negotiated history versions `1` and `2` remain readable, as do unnegotiated history reads. They offer no historical playback action. Boolean/unknown versions are rejected. Existing history entry schemas, original recording metadata and captured reply artwork are unchanged. The V1 wire examples and original qualification receipts retain their historical scope and are not current capability claims.

A legacy `play_history_item` command still validates its closed `{schema_version:1, session_id, entry_id}` reference and the original paired owner, readable retained row and source binding. It then returns HTTP `409`, `success:false`, error `historical_queue_preservation_unavailable`, with a localized explanation. It issues no play grant and performs no output inventory, chooser, transfer or play. A previously saved successful V1 exchange cannot supply a new successful response. Retained V1 output continuations also close before inventory or effect grants, including duplicate/new message IDs. Original read/source/retention errors remain closed. After RAM context loss, a saved output/play-choice receipt with an explicit retained `playback_observed` dependency also closes: V1 did not persist a historical admission marker, so that ambiguous archival playback provenance cannot become a new successful replay. Ordinary saved replies, output receipts without such a target and implicit current-playback evidence retain existing duplicate semantics. This narrow migration rule does not infer positive provider qualification from an absent dependency.

An explicit request version, runtime flag, provider-name hint, caller claim or synthetic successful adapter cannot enable this capability. Future support needs a separate reviewed provider protocol and original evidence proving atomic preservation, current owner/source/output authority and uncertainty handling. Append/skip, snapshot rebuilding and cross-endpoint ordering assumptions are not acceptable substitutes. This change supplies honest negative admission, not a delivered queue-preserving playback feature.

Ordinary recommendation/output playback retains its existing effect owner and semantics. Captured reply artwork, browsing and the current Session are independent. The denial is available in English, Dutch, German, French and Spanish. Clients hide historical play controls when the advertised capability is false and display the typed error for cached actions; they must never retry through ordinary play.

Qualification uses real paired HTTP, SQLite/Profile/Session owners and synthetic provider boundaries with no network, paid model, provider or device effects. A/B/A is a synthetic occurrence-preservation tripwire for denied operations, not positive Spotify proof. Unit regressions include legacy continuations, duplicates/concurrency, untrusted capability claims, strict versions, source withdrawal and an ordinary output-play control. Source, CI, installed runtime, native and physical acceptance remain separate.
