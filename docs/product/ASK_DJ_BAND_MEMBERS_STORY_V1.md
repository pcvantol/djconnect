# Rich band-membership answers and original public photos v1

## Product behavior

A named question such as “uit welke bandleden bestaat linkin park?” must receive
the supported band members and roles first, followed by connected background in
the selected DJ Persona and Mood. Club DJ is warm and witty when the subject
permits it; membership facts are not an artist/title/genre metadata template.
Two or three paragraphs and roughly100–180 words are an aspiration when the
retrieved evidence supports that detail, never a reason to invent filler.
Current, former, touring and guest members remain distinct. Sparse, contradictory
or outdated evidence must be described specifically; a clear membership question
does not justify asking the user which musician they mean.

## Shared Core execution

Direct and interpreted membership questions request original artist paragraphs.
A fresh canonical Wikipedia musical-group lead with one original QID selects the
band presentation; the focus/model label never establishes identity or facts.
The existing exact-artist corpus, one complete draft, source IDs and answer-word
review own acceptance. Generation/review uses the original configured Task when
present. A genuinely absent Task selects the already qualified conversation agent
before any I/O, with the same strict parsing/review; a failed or malformed explicit
Task never triggers a second provider path. Two model turns, or three including
semantic reading, remain the original cap. No repair/retry model attempt is added.
The existing public research16request/20second bound and independent-publisher
scheduling remain. A blocked generator/reviewer is not repaired with memorized facts.

## Band photograph

A source-proved group QID may use the existing artist-photo Commons P18/P180,
licence/credit and pixel decoder. The optional photograph has a separate single
8second allowance, at most five reads and one selected image; no failed-image
retry. It does not borrow current-track artwork or fabricate a Spotify identity.
A group photograph is not evidence that every pictured musician is a current member.
An unavailable photo does not discard an accepted textual answer.

The existing image proxy has a typed band- capability namespace. It serves only
original validated RAM bytes, never a second network fetch, for at most300seconds
and never beyond the original evidence/owner lifetime. Boundaries include original
pairing/Profile/provider entries, account/token/configuration epochs, committed
privacy revision, request identity, original UTC and monotonic anchors. Rejection,
expiry, committed clear/targeted forget/trim, provider unload or HA stop scrubs the
pixels and authority references. Maximum32images/8MiB total/2MiB per image.
No URLs, pixels, grants or renewal state enter Store. A restart does not recreate
an expired original photo lease.

## Additive client contract

Normal Ask DJ replies, assistant_message and ordinary history use images[].
Owner Session timeline page, tail/anchor window and entry-open add images[] only
for conversation_dj entries whose original client_message_id has a live photo.
The exact original URL is retained across those reads; reads do not fetch or
renew. An expired/withdrawn photo is omitted. Dependent source/model entry reads
explicitly exclude these temporary presentation capabilities.

Each image includes url, title (the asked-about band), subtitle, kind:artist_image,
source:wikimedia_commons, subject:{type:band,wikidata_id:Q…}, attribution (provider, file page, author,
credit, licence, licence URL, revision), width/height, original expires_at,
cache_policy:private,no-store and requires_device_auth:false. Render the complete
credit/licence, respect expiry and never substitute a previous bubble’s image.
The short capability intentionally permits headerless public-photo GET. Supplied
auth/device headers must pass original device authorization; empty, partial,
duplicate or wrong headers cannot downgrade to headerless access. Never send
provider credentials to Commons. Existing authenticated history/session access
and all playback/effect permissions remain unchanged.

Apple must decode this optional Session entry field and pass it to the ordinary
bubble’s image renderer, independently of session_media/current artwork. The
personally read local Apple a57e016 snapshot lacks that field; this is an explicit
client adoption requirement, not proof of the remote or installed client version.

## Delivery and acceptance

One owner-requested PR includes source, tests, current original HA fixtures and
closing documentation. No separate Final. Source review, CI/protected delivery,
real generated prose review, installation and client acceptance remain separate.
All24 requests/nine gates, Help EN/NL/free Send, VibeCast, push, Pi and production
work retain their existing scopes. No model qualification flag is changed by the
synthetic proofs in this increment.

The shared Commons parser supports its exact original-file-bound thumbnail CDN
as well as the existing upload host. The original filename/hash path must match;
query tracking is stripped before GET. Original source identity, permission,
licence, byte and decoded dimension checks remain. The requested1280pixel tier
is never accepted as proof of actual image dimensions.
