# Original Session/source adoption DATA

This private producer records the original source selection of an actual paired
Session start. It does not enroll a device, create a principal or grant push,
Activity start, background-read, signing or provider authority. Existing public
surface roles remain unavailable. Neither this origin UUID nor its private phase
revision substitutes for the af201 source_id/source_revision, native
source_generation or a presentation/target identity.

## Actual original continuation

The authenticated Session-start handler captures the already committed Profile,
actual MusicAccount/provider, entry/configuration, pairing revision and auth
tuple before discovery awaits. It allocates one original origin UUID, separate
prepare/accept/terminal operation UUIDs and two nonce hashes. Only that original
request task can bind the actual newly created Session ID and attach its
original observer. No GET, startup, cache read or later observer can mint or
reconstruct that root.

The shipping manager first commits the ordinary OPENING Session. Its source
preparation seals the original planned Broadcast and settings axes, then reserves
one journal row and all three operation identities. After the ordinary ACTIVE
transition commits, the manager publishes its actual active Session/Broadcast
and source selection, then accepts the source record with original guards.
These are separate transactions: partial or lost acknowledgement is not an
atomic adoption claim. Unknown outcomes never authorize reissue or a new UUID.
Missing or unavailable source-journal preparation leaves ordinary Session
behavior available; cancellation retains its actual committed SQL state.

The post-narration continuation can start an observer only for its own original
Session ID and Broadcast. A delayed older request cannot replace a newer
Session's observer, even when both requests use the same integration runtime.
Attached observers retain exact runtime, owner, Session and map identity checks.

## Committed continuity and negative fences

Source DATA has a dedicated committed observation. Only a genuinely already
loaded cached Store read preserves that original source observation. Queued
writes, actual saves, failed/uncertain settlement, manager replacement and
restored data close it. The existing generic Help snapshot still invalidates on
the same cached read; its publication rules are unchanged.

Profile/source/settings changes, runtime or observer retirement, cancellation
and Session end synchronously retire pending/live source roots before lock or
storage awaits and drop original runtime/config/source references. Retirement
uses only the original reserved terminal operation and row. Restoring equal
values or a later observer cannot reopen it. The old public pairing-role fence
remains retired after ordinary pairing; new original source DATA does not reset
or borrow that public authority.

## Bounded SQL18

Migration18 adds djconnect_source_origins. It stores opaque original operation
IDs, scope/nonce hashes, the existing Session relation, original UTC milliseconds
and phase/revision: prepared0, accepted1 or retired1/2. It stores no tokens,
credentials or raw Profile/source configuration. Capacity is 4,096 retained rows
and 12,288 reserved operation slots. Matched retirement requires no new capacity.
There is no eviction, restore adoption, reset, retry or replacement identity.
Verified WAL/FULL settlement and cancellation guards reuse the existing provider.
The local phase revision is not a playback sample ordinal or remote grant epoch.
