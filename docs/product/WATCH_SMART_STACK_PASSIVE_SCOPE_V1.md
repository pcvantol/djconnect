# Paired Watch Smart Stack passive scope v1

Owner-requested source candidate, not installed/native/device/background admission.
The direct human request is Smart Stack track name plus album cover in confirmed
Session Mood color, explicitly no DJ contribution and no progress requirement.
This selects an independent minimal paired Watch presentation purpose; it does
not reinterpret an iPhone widget grant or private Watch foreground/Flow data.

## Existing family, separate exact purpose

Reuse the existing /session/surface/authorize, /read and /image routes with
contract_version1, surface:watch_widget and projection_version1. Capability
advertises this optional scope independently of rich iOS/macOS projection3.
Only client_type:watchos with its own matching djconnect-watchos install identity
and ordinary paired bearer is accepted. iOS/macOS cannot request it; Watch cannot
request phone widget/live_activity scopes. No phone proxy grant, foreground cache,
App Group data or WCSession response becomes a Watch widget credential.

The same existing owner/active Session/entry generation/Profile/privacy/provider/
account/current-source fences apply. Explicit enabled:true, os_snapshot_cache:true
and locked_display:true are required in the Watch's own foreground consent flow.
Authorization creates a separate opaque entry+surface grant and generation; read
never creates it. Pair rotation, owner/source/account replacement, unlink/end,
disposal, revoke or expired source evidence withdraws the original purpose. No
restore, preference signer/key/epoch, enrollment or authority tuple is invented.
#1439 and actual Watch pairing/device acceptance retain their independent gates.

## Closed minimum resource

schema_version1, scope:paired_watch_widget_v1, surface:watch_widget; original
binding/generation/Session/sequence/revision, as_of/observed_at/expires_at and
active/stale/withdrawn state; bounded current_watch_widget_only cache policy;
confirmed mood value/revision; optional now_playing and artwork plus their
independent typed unavailable reasons. No contribution, Persona, Presence,
progress, queue/history, Ask DJ, DNA, voice or playback action is projected.

now_playing contains only original item_id/subject_uri, track name, original
observed_at/expires_at, source_url/provider attribution and the temporary metadata
usage basis. Artist/album display fields are omitted. Artwork contains at most
one already prepared independently qualified exact current track/album cover;
retain necessary original subject/attribution/five-language accessibility and
original asset expiry. No contextual-contribution image, artist photograph,
private foreground URL, guessed title match, new fetch or crop/overlay permission.
The selected source-purpose interpretation is bounded first-party Watch display
of the same necessary temporary metadata/cover category, subject to exact owner
review; no blanket provider-policy expansion or new external redistribution.

Explicit paired_watch_cache:true describes only this independent Watch purpose.
watch_replication:false remains: the result cannot be copied from/to another
surface/device, external relay or public cache. A Watch image GET must present
that same Watch's original surface/grant/version and paired identity. Grant or
image possession alone is not authentication. Phone grants cannot fetch Watch
pixels; Watch grants cannot fetch phone/contextual-contribution pixels.

original cover/source deadlines. Read/redraw/Mood/cache writes cannot refresh old
track/cover evidence. Neutral on expiry/uncertainty; native supplies the small

Background delivery remains false. Real Watch widget entitlements/shared-store,
explicit own consent, paired identity, physical Smart Stack display and any
independent background/API/APNs chain must be qualified separately. No native or
live pairing/grant/runtime action is performed by this source increment.

Offline proof must cover real disposable Watch pairing and own consent, exact
