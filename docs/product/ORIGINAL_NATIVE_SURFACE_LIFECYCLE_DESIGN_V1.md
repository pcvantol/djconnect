## Concrete next result

One jointly reviewed canonical lifecycle contract must let Apple implement a
separate status native owner and durable once adapter. It must identify exactly
which real Core continuations supply pair/source inputs, which independent
authority is still missing, and what each transaction can actually acknowledge.
It must not turn matching DATA into permission or make a source-only port look
like a deployed positive producer. No new UI is needed after genuine pairing.
No key/signing/provider/device execution belongs to this design or its review.

## P0–P5 transition contract

P0: evaluate genuine pair/source/native inputs and independent start decision.
Missing, expired, retired, mismatched, cancelled or unverified input -> CLOSED,
zero native calls. No cached positive decision or plain DTO can pass this gate.

P1: bind the exact independent decision to ONE original presentation and ONE
dispatch operation in the actual owner transaction; its signed grant/nonce
cannot be reused for a second presentation, process or Session. A returned
presentation is bound back to that same decision before any SDK admission.
This binding requires explicit field-by-field original joins, not merely equal
policy hashes or an independently generated new UUID. Retain original
presentation/operation identity and reserve all ordinary and
terminal obligations in the actual Apple local transaction. Capture original
positive/negative storage witnesses and cancellation state before waiting.
No partial ACK produces a usable handle. No two-store/OS/API atomicity claim.

P2: commit consumed native dispatch BEFORE invoking SDK. Lost ACK, cancellation,
process/actor/storage identity replacement or ambiguous commit -> UNKNOWN,
no SDK and no reissue, even if a later SQL read finds matching bytes. A complete
ACK returns only the original process-bound handle; final same-original
currentness/clock/cancellation check has no suspension point before invocation.
The consume ACK is a private nonserializable process-bound handle, not a DATA
receipt that a second caller can parse to manufacture another dispatch.
A synchronous local spent latch is set before entering any SDK wrapper; a
wrapper/actor hop that can suspend requires another original fence at its
actual invocation boundary. No taskless or new-task callback adopts the handle.

P3: invoke distinct status SDK once; retain actual returned Activity.id even
when positive authority retires during creation. Such late completion grants
no registration or read/update right. Cleanup may follow only its independently
preaccepted original terminal scope and own consumed attempt. SDK error, lost
reply or missing Activity inventory never proves creation did not occur.

P4: join actual Activity.id to original presentation and af201 native descriptor.
The actual local Activity token acquisition and original generation-fenced
token observer needed to prepare native proof are permitted ONLY by the
independently admitted original local native start/acquisition scope. They
need not wait for A/B, which depend on that proof. They supply no remote
registration, continuing content read or update right.
Only now may the new native proof/actual-target enrollment obtain its own
definitive API A acknowledgement, followed by the narrower original status B
under that exact A. No P0 permission is relabelled as an enrolled A/B. Local
SDK creation success is not proof of either API acknowledgement. Native A
enrollment uses its own original enrollment authority and completed proof; it
is not gated by the B it will parent. Continuing remote-content registration,
reads and updates require the same accepted A/B authority and original target.
Local proof-input observation is the distinct scope above.
Token callbacks retain original task/actor/app/Activity/presentation/authority
identities; A -> nil -> A cannot revive a retired generation. Use original
Core observation timestamp, never arrival/local Date/token or SQL commit time.

P5: close local admission synchronously before ANY retirement await. Record
terminal outcome against the original reservation only. UNKNOWN remains
consumed; status, build upgrade, launch, cleared Defaults, changed operation ID
or equal restored context cannot start again. Authorized inventory reconciliation
requires exact original real Activity.id + both attributes; zero/multiple/
mismatched results stay unresolved. No firstMatch adoption or ending unrelated
Activities. SQL terminal ACK, SDK end return, API withdrawal and APNs/native
reception remain different observations. Respect actual user/OS dismissal.

## Widget-specific path

Device transport eligibility is installation-scoped and independent of an
active Session. Current WidgetKit token/configuration is native input DATA,
not a grant or proof of an individually addressable placement. Signed app/
extension/platform/environment/kind evidence is validated independently.
Actual native grant_epoch, target_generation and Core source_generation are
separate ORIGINAL owner values with a retained mapping, not pair/task/sample
UUIDs or converted A/B integers. No producer for these values exists yet.

Widget reload fans out and is not content authority. Each background timeline
read requires its own accepted finite status B/read custody, original clock
and source/restore witness. AppGroup currentProfile, foreground host snapshots
or the transport token cannot supply this permission. No cross-Profile fallback.
The canonical fanout policy must accept the complete finite signed projection
scope before enrollment; missing policy stays closed, never fake placements.
A nil/error local token closes acquisition; remote withdrawal requires its own
original acknowledged operation. Old OS display may remain as selected by Peter.
No titles, artwork, progress, rich Moment text or refreshed observation time.

### Closed semantic outcomes (not a new JSON wire)

A reservation returns exactly ORIGINAL_RESERVED(original private handle),
DENIED(exact pre-effect reason), or UNKNOWN(original operation identity).
Only ORIGINAL_RESERVED can be consumed; duplicate/status/restart never returns
a usable handle. Consume returns ORIGINAL_CONSUMED(the same handle), DENIED
(before commit), or UNKNOWN; unknown commit remains spent. Native invoke is
not represented by a boolean SUCCESS: capture actual SDK_RETURNED(original
Activity identity) or SDK_OUTCOME_UNKNOWN, preserving the consumed reservation.
Terminal bookkeeping, native end and API withdrawal each have their OWN
ACKNOWLEDGED/DENIED/UNKNOWN result and original operation. No generic success
shape crosses these transaction domains. DENIED applies solely to its OWN attempted transaction. It never means
NO_EFFECT for the whole workflow, frees a previously committed P1 reservation,
unconsumes a native dispatch, restores capacity, or proves OS/API nonexecution.
A precommit denied consume leaves all acknowledged P1 reservations and original
operation latches consumed; terminal failure similarly retains prior truth.
There is no automatic stage retry or replacement identity.
Actual error code/wire grammars must
be jointly specified before a cross-process producer is implemented.

Vectors are declarative requirements, ZERO execution claimed by this design.

## Required live trust-source admission matrix

The following are explicit unresolved inputs, not newly selected providers.
No live factory may be enabled until each applicable row has an exact owning
source, concrete current instance, original acquisition receipt, negative
variants and separate qualification. Static code/entitlements, JWK in the same
response, a test owner or a public fixture cannot satisfy a row.

* Core purpose/status-start: concrete registered installation/principal and
  independent purpose/policy owner; current source and pair original relation;
  exactly signed new start-permission grammar. Missing/revoked/unknown = CLOSED.
* Apple signed host/native: platform-specific actual signed installed app/
  extension/environment, original OS capability/lifecycle and original native
  proof acquisition. Current codesign output or DEBUG is not an original live
  witness; unsupported/unknown platform closes rather than cross-family fallback.
* Core/API/Apple clock: original UTC/continuous-clock anchors and accepted rate/
  lifetime mapping across all process domains, original expiry and conservative
  remaining bounds. No network-arrival/local repaint renewal. Missing or lost
  original anchors/unsupported restart mapping = CLOSED. No numeric TTL chosen.
* Apple storage/restore: actual durable pre-SDK consume acknowledgement,
  independently qualified VFS/failure/nonrollback/restore identity and reserved
  terminal capacity. SQLite/Defaults consistency alone is insufficient;
  lost ACK/replaced provider/uncertain restore = UNKNOWN and no positive reissue.
* Cleanup/withdrawal: concrete original negative authority bound to exact actual
  native identity, separately consumed operation/nonce/budget and own response.
  No actual returned identity or independent terminal authority = no native end.

Until those sources are supplied this successor can qualify only closed typed
interfaces, parsers, state transitions and synthetic causal behavior, not an
actual start/admission factory or device acceptance. This is a specific live
implementation dependency, not a request for another user approval screen.

## Original API ownership clarification

API source currently supplies transcript parsing and DATA reservation/status/
terminal journals, not a live native reservation/status/end port for Apple.
They are not substituted for Apple durable SDK reservation/once or Core start
permission. The source-currentness decision, native SDK effect, API A enrolment,
B status/read admission and terminal operations remain distinct transactions.

The earlier R1/R2 dependency on accepted A/B before P0 was a Root design error;
it is preserved with the original owning API finding. R3 removes that circular
precondition. No published contract or existing runtime was changed by R1/R2.
