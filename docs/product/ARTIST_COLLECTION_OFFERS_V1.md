# Read-only artist album and playlist offers

The reported Dutch request `Heb je iets van de artiest haevn` and an English
request for something by an artist offer up to five real albums and five real
playlists. They do not start, queue, transfer or change playback. A missing
original failed request receipt is not replaced with an invented error cause.

The existing semantic read interpreter may select `artist_collections` with a
closed named reference. The initial named-only route supplies only a public
artist name, never provider URIs, output choices or executable arguments.
Core independently resolves the canonical Spotify artist and qualifies rows.
The same owner/Profile/account/turn and original reference fences surround all
provider awaits; no failed name lookup falls back to another contextual artist.

One bounded backend collection read resolves artist identity, reads at most one
20-album page and one ten-playlist search page, and checks at most ten candidate
playlist first pages (50 items each) for that artist's track credit. No page
continuation, top-up, public-playlist-ID guessing, web scraping or write occurs.
Only the canonical artist's credited albums, consistent typed URI/IDs and
credited playlist candidates qualify. Deduplicate each category and cap it at
five. Full and partial category counts describe actual evidence; a denied,
missing or unavailable category never erases verified records in the other.
Timeout and scope withdrawal remain closed and cannot trigger automatic retry.

Use existing ordered `items`, `playback_actions` and original server-owned
result-set/choice-action machinery. The two kinds remain album and playlist;
no model authors titles, rows, IDs or playback grants. Selection is a separate
explicit existing operation against the original result set and source.
All five UI languages have literal count/availability copy. Targeted failing
wording qualification is Dutch and English; preserve other languages and the
independent Help publication boundary. No new paid/model/native acceptance is
inferred from isolated fixtures. Source, protected checks, exact owner approval,
merge, separate Finalization, HA-dev debug composition/install/readback and
real provider/native outcomes remain separate gates.
