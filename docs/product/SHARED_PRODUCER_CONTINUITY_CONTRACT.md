## Policy fixed before production mutation

Two independently identified recordings, each with a fresh attributable credit,
may connect only by exact valid contributor MBID and explicit unqualified
producer role. Any role attributes, ended relationship, malformed identity,
conflicting contributor labels or absent proof exclude that contributor.
Names never establish identity. Historical proof retains its original playback
identity. A closed derived relation validator checks both proofs; the ordinary
provider-fact allowlist remains closed.

Runtime retains normalized proof only after recording-credit Flow publication;
at most the last three different observed tracks, each within 30 minutes.
Observation evicts older tracks even when they had no published credit. End
clears proof and relation-use state. No unpublished proposal starts continuity.

Only Discover AND Exploring may offer one shared_producer candidate. Choose
the most recently observed eligible predecessor, then the smallest contributor
MBID; source order has no effect. Current/historical recording IDs must differ,
and labels for the same contributor must agree. The unordered recording-pair
and producer key cannot repeat; at most one connection per current track.
Use state changes only after actual publication. Read-fit, capabilities, source
freshness, current observation and all cadence/cancellation gates still apply;
this card counts in the existing six-card limit. Other facts retain #1122
ranking. No valid/usable relation gives ordinary facts or silence.

The existing track Moment names current and earlier recording plus producer in
exact en/nl/de/fr/es copy; it asserts no exclusivity, collaboration or influence.
Current playback supplies Now Playing/artwork. Both public recording URLs are
attributed; a second optional URL is a compatible VibeCast projection extension.
Genre→Track and Recommendation transitions remain unchanged.

The owner additionally requested semitransparent, glass-like DJMoment bubbles
on this candidate. The existing VibeCast bubble uses a translucent tinted fill,
soft backdrop blur, light edge and inset reflection. Its layout, source links
and card lifecycle remain unchanged; opaque fallback and reduced-transparency
preferences preserve legibility. Browser evidence covers the resulting cards.

## Before/after scenarios defined before source changes

1. Publish recording A credit, then observe B with two shared producers and a
   different artist: before ordinary B credit, after one explicit A↔B producer
   contribution with deterministic ID choice and two links, in all five locales.
2. Same name/different ID, wrong or qualified role, absent URL/ID, conflicting
   label, ambiguous recording, same recording, expired proof, unpublished A,
   other Session: ordinary facts or silence; never a connection.
3. Permuting source relationships leaves the choice stable. Repeated events,
   reconnect snapshots, seek/pause, source switch and late results neither
   consume unpublished proof nor publish stale/duplicate cards.
4. A rejected read-fit/capability candidate remains unused. Manual/Continue and
   existing rank/dose/attribution/transition tests remain regressions. Observe
   four different tracks and end: eviction/disposal is measurable.

Acceptance requires the real Runtime ingress → Planner → Knowledge → Moment
→ Flow → Broadcast and actual existing browser consumer, visible before/after
sequences, portrait/landscape and exact current artwork plus two attribution
links. Software fixtures are distinct from live provider/HA/Pi evidence.
Pi capture/frame-rate remain PARTIAL/parked. Source and separate Finalization
merge each require a bounded decision for automatic internal publication.
