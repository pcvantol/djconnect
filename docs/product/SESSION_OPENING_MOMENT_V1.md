# One retained Session welcome

Owner refinement, 18 October 2026, within the existing personal-DJ restoration.
The existing `session` DJMoment has one special opening purpose, generated by
Core after confirmed Profile defaults are inherited and before automatic track
contributions. It welcomes the listener, names and explains the actual starting
Mood, Persona and Presence, and wishes them an enjoyable Session. It makes no
claim that music started or that the DJ selected a recording.

Use the existing HA narration owner and its independent assessment/two-call
limit. The brief contains only the three confirmed choices and their meanings,
with no account, device, voice-provider, listening or catalogue data. A complete
localized welcome is the honest fallback when expression cannot qualify; it is
not evidence of successful generated storytelling. Five language families and
all four Presence levels ship together.

The existing Moment/Flow/Broadcast/history/speech owners remain authoritative.
There is no new endpoint or public Moment type. Existing generation metadata
identifies `purpose: session_opening` and the original three choices. The same
metadata is retained with the accepted body. It is descriptive, never authority
for playback, source processing, a voice choice or another publication.

One Runtime-owned start snapshot and one in-flight operation per Session prevent
retry/reconnect/concurrent start from generating another welcome. The opening
text and starting choices never change after acceptance. A settings change
during generation discards stale generated expression and uses the original
start snapshot, subject to current owner/privacy/lifecycle admission. No model
work runs under the Runtime lock. End, owner withdrawal or failed storage cannot
produce a live-only welcome. Read-only history never calls the model.

The informative opening also exists for `music_only`, with zero automatic
speech on client or HA speaker. Manual replay still follows current output,
voice, ownership and source admission. Non-silent Presence levels debit the
existing readable contribution interval; the welcome does not create a second
frequency policy. Other proactive contributions wait while the opening is being
prepared. History opt-out, clear, source withdrawal and whole-Session rolling
retention retain their existing semantics.

Qualification must prove actual commit/reopen, original-setting immutability,
deduplication, generation outside the lock, cancellation/withdrawal/SQL failure,
zero automatic Music-only speech and no musical mutation. Source/model fixtures
do not establish generated quality, installed, native or audible acceptance.
