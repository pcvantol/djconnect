## Contribution exploration and rich answers

One content tap submits the existing Ask DJ message with selected_entry or
selected_moment. Generic localized Tell me more is a valid question. A typed
attribute is optional: the existing read interpreter may propose a public
research subject/angle from the admitted contribution, never a guessed URI,
fact, playback grant or unrelated current track. Core validates this proposal
against qualified public context before bounded Wikipedia/official-site/web
retrieval. Existing owner/source/expiry/history/clear guards remain mandatory.
Selected subjects must match the complete qualified name; excerpt words alone
cannot authorize a subject. A newly named public subject must be anchored in
the actual question, with bounded typo tolerance that never drops name parts.
Exactly one extra interpretation call is permitted for a validated research
plan; generation and independent evidence review retain their own calls. No
format retry or failed lookup buys another allowance.

Informative researched answers use confirmed Persona/Mood/language, useful
documented details and one relevant final follow-up question. Questions must
not smuggle unsupported factual premises. Follow-ups keep the same qualified
subject; an explicit new topic supersedes it. This rule does not add questions
to controls, failures, result captions or Silence. All five locales apply.
Rich artist stories and licensed artist imagery reuse the earlier consolidated
research/variety/artwork work; source tests are not actual narrative acceptance.

## Mood music steering

Only an accepted user Mood transition can initiate the follow-up. Same-value,
replayed writes, reads/reconnect, slider preview and Profile-only changes do
not initiate another question. The existing Ask DJ/Flow owner accepts a bounded
question/proposal using current Mood, permitted DNA/Discover, actual queue and
playlist/library and local time. Generation is nonblocking and superseded
Mood/Session/owner revisions cannot publish or execute stale work.

Proposals themselves do not change music. Named actions are qualified against
the actual backend and bind exact owner/Session/Mood/proposal/action identities.
NEXT means next without interrupting; queue replacement means the full promised
effect, not an append or just one track. Spotify's append and start-context
endpoints do not establish these stronger guarantees. Unqualified next/replace
actions must be explicitly unavailable, never relabeled Play Now. A supported
library-context action says start now and retains full album/playlist identity.
Any generated mix is labeled DJConnect-curated unless Spotify itself supplied it.
No silent library writes or Music DNA opt-in. Explicit choice, existing effects
and idempotent receipts own execution; actual provider readback owns success.
