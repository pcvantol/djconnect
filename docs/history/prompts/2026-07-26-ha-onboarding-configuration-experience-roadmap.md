## Archived prompt

Register the future **Home Assistant Integration Onboarding & Configuration
Experience Assessment** as one assessment-first Product Development capability.
Its central question is whether a new user without DJConnect knowledge can go
from a Home Assistant installation to a first successful DJ Session through
understandable choices, clear device instructions and recoverable errors.

The future assessment must cover the existing path from adding the integration,
configuring a first Profile, selecting/authorizing a Music Backend, optionally
qualifying Assist and voice, pairing and mapping a first host, to safely
starting a first Session. It must examine: initial setup; Profile onboarding and
CRUD; Spotify Direct/Music Assistant selection; Spotify OAuth and
reauthorization; Assist Pipeline/voice readiness; Apple, Windows, Pi, ESP32 and
Voice Host guidance where supported; Options/recovery UX; product language,
accessibility, privacy and security; and objective setup-completion evidence.

The assessment must retain existing ownership: Product Development owns the
experience; the Home Assistant integration owns any later delivery; Platform
Evolution contributes only pairing, connectivity, privacy and qualification
evidence. It cannot reveal credentials/tokens/private data, alter pairing or
OAuth, create Assist Pipelines, start Sessions automatically, invent QR or
download flows, or introduce a parallel roadmap.

Position it after Client Connectivity & Resilience qualification and relevant
CMB-05/CMB-06/CMB-07/CMB-09 host-profile evidence. Keep it outside the current
Execution Horizon. Use it as a future input to Public Release Readiness and
Apple Premium Experience onboarding/polish without reordering either roadmap.
Possible later delivery candidates remain independently authorized bounded
slices for initial setup, Profile UX, backend guidance, OAuth UX, Assist
guidance, host pairing instructions, recovery information architecture,
localized/accessibility copy and first-Session readiness feedback.
