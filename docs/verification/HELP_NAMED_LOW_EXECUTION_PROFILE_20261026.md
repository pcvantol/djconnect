# Named low Help qualification profile — 26 October 2026

This change adds a separately admitted `help_low_v1` development profile. It keeps
`gpt-6-luna`, 3,000 maximum output tokens, the original questions, Core deadlines,
full source corpus, semantic and style reviewers, role bindings, and answer-word
proof. It does not qualify or publish the Help catalogue.

## Why this is a distinct experiment

The original medium-profile five-case run `40272162630` produced three accepted
stories, one complete English style rejection without an explanation, and one
French review with the explicit `max_output_tokens` incomplete reason. The
French review concerned one generated draft. The original strict receipt keeps
NULL SDK totals and failed word proof; the separate diagnostic reports 20
reserved attempts and 19 completed responses. Those results and their permanent
claims remain unchanged. This is not a retry, a repaired old result, or evidence
that lower reasoning effort will improve quality or latency.

The same `help-content-development.yml` workflow accepts an optional closed
`qualification_profile` choice. Omission retains `help_medium_v1`. There is no
free model, effort, token-limit, provider, or production-configuration input.
Unknown or malformed profiles close admission. The trusted descriptor enters
content identity, the exact candidate pin, phase revalidation, and report checks.
The report cannot choose its own expected profile.

Medium and named low each bind five control files, including the setup program
actually executed. The new fixed low setup program checks the real pre-network
REST payload: exact model, low effort, and integer `max_output_tokens == 3000`.
The existing fixed medium and consumed legacy setup files remain byte-preserved.

After the original once reservation, the controller captures a public fixed
profile descriptor in the private lab before reading the test credential. The
child verifies this bounded, non-symlink, single-link file with unique JSON keys
and exact types before importing the HA execution scenario. A lost or changed
low selector cannot silently run medium. Historical standalone medium fixtures
retain their original no-marker compatibility; a present marker is always checked.
