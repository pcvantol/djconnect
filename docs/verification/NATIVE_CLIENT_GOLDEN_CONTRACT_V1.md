# Native client Golden consumer contract v1

Status: SOURCE_PROTOCOL_ONLY. No installed/native fixture is admitted by this
source or by the generated inventory. execute:false is mandatory. This increment
enables reviewable client mapping and fail-closed regression, not an alternative
Runtime, authority system, diagnostics endpoint or scenario driver.

## Scope and immutable source

Cover ordinary iPhone/iPad/Mac/Watch Ask DJ questions/answers, Session contributions,
14 Help/suggestion routes, For-you and music announcements. Reuse existing product
routes and source IDs. The canonical inputs are the current release matrix,
single-turn fixture named by that matrix, five-language Help catalogue, Moment
persona/mood matrix and qualified For-you/music-announcement producer receipts.
Each input has its exact repository path and SHA256. A public catalogue contains
canonical source prompts only, never a private user's prompt/history.

Inventory preserves every current family/step ID, question, expected answer,
explicit language (or null), verbatim model policy and evidence boundary. An old
39-family/167-step consumer pin cannot cover current source. A missing explicit
locale, native driver, fixture precondition or typed transport budget is a
BLOCKED mapping, never a skip or translated-by-setting-language PASS. The English
and Dutch catalogue questions are exported only when those exact source rows
exist. All five product localization families remain unchanged.

Every native mapping names one original source case reference, exact locale,
client (`iphone`, `ipad`, `mac`, `watch`), ordinary driver, prerequisite evidence,
expected visible answer/effect, allowed effect target and its model/transport
policy. Device-specific absence is an expected negative result only if bound to
that device's normative capability; it is not permission to suppress the case.
Watch consumes the original supported Session/Ask DJ projection; no latest-Moment
substitute, phone-local response, fabricated authority or APNs inference.

## Gates

1. **Source protocol**: protected exact contract/inventory and consumer parser
   qualification. Pure validators and synthetic negative vectors prove only this.
2. **Installed producer/consumer**: independent exact Core source/install receipt,
   actual app source, executable/build and catalogue/adapter hashes for each client.
3. **Disposable fixture admission**: independently owner-approved real Profile,
   music-account/backend, Session incarnation, paired device identity and exact
   output/audio/effect scope. Ordinary owner routes create/read the fixture.
   No personal history clear, credential widening, automatic re-pair, authority
   tuple/key invention or self-declared qualified:true. A fixture proof must be
   supplied from the real owner, independently pinned outside the native report.
4. **Manual run**: an explicit bounded operator authorization binds the same run,
   selected complete case set, actual clients and fixture, cumulative grant ledger,
   total transport/provider/model/token/audio limits, UTC expiry and original
   monotonic deadline. New run IDs/processes/batches never reset cumulative spend.
   No automatic retry/resend/fallback. Existing private observer ceilings remain
   authoritative; a case needing unsupported policy/client coverage is BLOCKED.
5. **Evidence and independent review**: original native request/case/client-message,
   actual server assistant ID and text digest, same-run reopened Profile history,
   original Session entry/contribution and Watch projection; actual provider
   pre-I/O reservation, terminal/model/usage/error and independent backend readback.
   Failed/cancelled/unknown/unattributed attempts remain counted. Zero-model cases
   require zero actual attempts; model-required cases cannot be changed to zero.
   Text/supported booleans/hashes alone prove no origin, semantics, playback or audio.
6. **Public safe report**: only closed-schema IDs/digests/counts/verdicts. No secrets,
   URLs, prompts, answers, raw exceptions, tokens or raw Profile/Session/device IDs.
   Producer/fixture receipts must match independent expected pins, not report-owned
   labels. Missing evidence remains incomplete; an offline result never grants
   native/runtime/release qualification. Independent editorial/effect/audio/device
   acceptance and full selected-set coverage remain separately explicit.

The existing private `native_golden_attempts.py` is a bound-client observer, not
fixture enrollment or all-installed-provider coverage. This contract does not
install it into live HA or authorize a paid run. Unsupported provider transports,
model-policy prose, absent localized steps, private-owner native mappings and
producer export qualification remain explicit work; the compiler lists them.

## Execution and regression policy

The manual native suite is selected for a release/relevant change or explicit
operator run. Per-PR checks validate source pins, all-case enumeration, exact
locale/ID-to-policy binding, client coverage, no-retry budget, missing/duplicate
request/answer/history/readback, origin pin mismatch, stale fixture and safe export.
They perform no provider/native I/O and do not create fixture authority. Real
native execution remains on the owning Apple runner through the ordinary app;
no silently skipped client, missing family or old manifest may become integral PASS.

`tools/verification/native_client_golden_contract.py` emits the current pinned
inventory and validates closed draft/evidence records offline. It deliberately
returns DRAFT_NOT_ADMITTED / EVIDENCE_PENDING_INDEPENDENT_REVIEW and execute:false. These are
usable schema/coverage outcomes, never a qualified live consumer export. The
source protocol can be reviewed and adopted by Apple without pretending that
its still-missing actual fixture/operator/provider/semantic receipts exist.

## Closed protocol records

The compiler's public inventory has exactly schema_version, contract_id,
qualification, execute, clients, selected_languages, source_pins, cases and
coverage. qualification is SOURCE_PROTOCOL_ONLY and execute is false. Stable
case references are `(source path, original id, explicit language)`; there is no
new global Golden sequence. 40 current EN/NL catalogue questions/chains are bound
to the ordinary Ask DJ flow and 28 catalogue entry-locale rows to pure Help GET.
Other rows retain explicit locale/driver/owner-mapping gaps. The existing 560
persona/mood/Moment cases and all 385 current conversation steps remain enumerated.
No new product scenario or factual expectation is invented by the compiler.

A draft plan has exactly schema_version, contract_id, inventory_sha256, run_id,
clients, receipts, app_receipts, starts_at, expires_at, budget,
retry_automatically and cases. clients is the canonical four-client array.
Every selected source case binds source/id/language/client plus the exact
canonical question_sha256 and model_policy_sha256; changing the question or
relabeling the locale/model policy is rejected. At least one selected case per
client is required. Full-suite coverage is a separate requirement, not inferred
from a selected batch of at most 40 case-client rows.

receipts has exactly core_install, fixture_owner, provider_coverage,
owner_authorization and cumulative_budget SHA256 pins; independently supplied
expected pin maps and all four actual app-receipt pins are mandatory. These
pins are comparisons, not proof that a caller owns the original artifact.
Opaque legacy model-policy prose is preserved and remains unqualified until a
protected typed native mapping is supplied. Source-bound Help GET requires zero
model attempts; no Help catalogue ID is sent as an execution command.

budget has exactly provider_attempts (0...40), attempts_per_turn (1...2),
output_tokens_per_attempt (1...3000), audio_actions (0...40), grant_id_sha256,
cumulative_attempt_limit (0...1000000) and previously_reserved_attempts.
The canonical budget object must match the independently pinned current budget
snapshot. Previously reserved plus proposed attempts must fit its original
cumulative limit. A new run UUID cannot reset a pinned snapshot. This checks a
snapshot only: the live private owner still must reserve before actual I/O,
prevent replay across runs/batches/processes and never restore spend on failure.
The source protocol does not increase the existing private observer ceilings.

Evidence has exactly schema_version, run_id, plan_sha256, receipts,
unattributed_attempts and cases. Every case has exactly source/id/language/client,
client_message_sha256, server_object_sha256, answer_projection_sha256,
history_sha256, session_entry_sha256, provider_attempts, provider_terminal,
provider_receipt_sha256, model_sha256, input_tokens, output_tokens, semantic,
effect and native. For a Help observation, history and Session-entry hashes must
be null: a read cannot claim a write. Ask DJ/contribution evidence requires its
actual reopened history/entry relation. Complete nonzero provider terminals
require model/usage and original per-case provider-receipt digest; failed or
unknown attempts remain counted, with unknown usage nullable. Reusing a provider
receipt cannot count as a new independent turn. An aggregate digest still needs
independent actual transport origin/coverage, never a native self-report.

The public reconciliation remains EVIDENCE_PENDING_INDEPENDENT_REVIEW,
execute:false and native_release_authority:NOT_GRANTED even when supplied verdict
labels all say PASS. complete_selected_set means only receipt presence for that
batch. all_supplied_verdicts_pass describes supplied labels and terminal shape,
not independently proven truth or whole-inventory coverage. Unknown keys, raw
answers/prompts/credentials, wrong original IDs, stale pins, missing clients,
changed policy, duplicate cases and unattributed attempts fail closed.
